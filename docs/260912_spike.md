# ウィジェット疑似アニメ 実機スパイク

プラン `260910_dev_plan.md` §9 Phase 0 の 0-9〜0-11。判定は同 §12 の **D-11** に記録する。

作成 2026-09-12 / 判定 **未実施**（下見と 0-9a は 2026-09-22 に実施済み）

---

## 1. 何を決めるためのものか

ホーム画面のウィジェットを「動く窓」にできるか、「様子が変わる窓」に留めるかを決める。

iOS のウィジェット拡張は自分では動けない。1 日 40〜70 回の更新予算があるだけで、
秒単位の描画はできない。ただ `Text(timerInterval:)` だけは
**拡張が止まっていても OS が毎秒描き直す**。そこにカスタムフォントを当てて
絵をマスクすると、絵が毎秒出たり消えたりする。

これは **Apple が保証した手法ではない**。Bryce Bostwick が 2025-05 に公開 API のみで
実証したが（`research/E` §2.3、`research/F` §2）、

- Apple がいつ塞いでもおかしくない（Hackaday「don't expect it to work forever」）
- **Xcode 26.1 以降の SDK でビルドすると止まる**という報告が複数ある

ので、**手元の実機で確かめてから決める**。

### 手元の構成で測る意味

プランの 0-9 は当初「Xcode 27 でビルド、iOS 27 実機」と書いていたが、
D-15 で **macOS 26.5.2 / Xcode 26.6 / iPhone 17 Pro iOS 26.1 の据え置き**を決めた。

**この構成は、止まるという報告の条件（Xcode 26.1 以降の SDK）を既に満たしている。**
つまりここで動けば手元では使えるし、動かなければ手元では使えない。
Phase 3 まではこの構成で開発するので、**測るべきはこの構成**である。

## 2. 入れるもの

4 つのウィジェットを用意した。**本番のウィジェットとは別のターゲット**
（`app.charatime.spike`）なので、ここで何が起きても本番は巻き添えにならない。

| | 何 | 見るところ | 位置づけ |
|---|---|---|---|
| **A** | 静止した ● | 動かない | ほかを比べるための基準 |
| **B** | エントリ切替で ● が 1 分ごとに進む | ● が進むか | **Apple 公式の方式。最後の砦** |
| **C** | マスクフォントで 1 秒ごとの点滅 | 左 2 つが交互に点くか | 非公式。**判定の分かれ目** |
| **D** | 0.25 秒ずらした 4 本で 4fps | 点いている ● の数が増減するか | 非公式。C が動いてから見る |

どのウィジェットにも **2 つの読み**を出してある。ここがいちばん大事。

- **右上の秒のカウンタ**: `Text(timerInterval:)` をそのまま出したもの。
  **これが進んでいれば、OS はウィジェットを描き直している。**
- **下段の「絵を作ったのは hh:mm:ss」**: タイムラインのエントリが作られた時刻。
  **秒のカウンタが進んでいるのにこちらが古いままなら、
  拡張が動いていないのに画面だけ更新されている。** それがこの手法の要。

## 3. 手順

### 3-1. 先に 5 分だけ（0-9a）

App Store の **Pixel Pals** と **秒時計 for Widget** を入れて、
ホーム画面のウィジェットが秒単位で動くかを見る。

- 動く → C・D にも期待できる
- 動かない → C・D の期待値を最初から下げてよい（判定が早く終わる）

**所見（2026-09-22、iPhone 17 Pro / iOS 26.1）:
ロック画面と Dynamic Island では動いていた。ホーム画面は測っていない。**

| 見たところ | 面 | 秒が進んでいるか |
|---|---|---|
| ロック画面ウィジェット「22:44:27」（秒時計） | 面 1 と同じ WidgetKit | **進んでいる**。本体のロック画面時計は 22:44 で秒を出さないのに、ウィジェットは `:27` を出している |
| Dynamic Island の丸「38」（秒時計） | 面 3 | **進んでいる**。上の `:27` の 11 秒後で、分は同じ 22:44 |
| ロック画面ウィジェット「Hugo the Cat」（Pixel Pals） | 面 1 と同じ WidgetKit | 静止画からは判断できない |
| Dynamic Island の猫（Pixel Pals） | 面 3 | 同上。Pixel Pals の売りはここで、**面 1 の証拠にはならない** |

**これで分かったこと。** `Text(timerInterval:)` 系の文字は、iOS 26.1 の実機で
**ウィジェットの面でも毎秒描き直されている**。C が乗ろうとしている土台は生きている。

**まだ分かっていないこと。** 見たのはロック画面と Dynamic Island で、
**ホーム画面には両アプリのウィジェットを置いていない**（アイコンが並んでいるだけで、
入れる前と何も変わっていない）。3-1 が問うているのはホーム画面なので、そこは空欄のままである。

**これは「動かなかった」ではなく「測っていない」。** 上の分岐（動かない → C・D の
期待値を下げてよい）は**引かない**。動かなかったのなら判定の材料になるが、
置いていないのだから材料にならない。3-3 で A〜D を置くときに、
**秒時計のウィジェットも 1 枚だけホーム画面に置いて**、同じ画面で見比べる。

### 3-2. アプリを入れる

`scripts/ios-device.sh --install` で、ビルドから起動まで 1 コマンドで入る。
スパイクのウィジェット拡張はアプリに同梱されるので、別の操作は要らない。

```bash
scripts/ios-device.sh --install                  # 入れて待受モードで開く
scripts/ios-device.sh --install --screen spike   # 入れて下見画面で開く
```

初回だけ `.env.local` に署名の Team ID が要る（`.env.local.example` をコピーする）。
**Xcode.app は開かない。** メモリ 8 GB の機械では、開かないことがそのまま速さになる。

**無料アカウントの署名は 7 日で切れる。** 切れたら入れ直す。

### 3-3. ウィジェットを置く

**アプリを入れただけではウィジェットは出ない。** 1 枚ずつ手で置く。
Live Activity（Dynamic Island）とロック画面ウィジェットは別枠で、
そちらが見えていてもホーム画面には何も出ない。

1. ホーム画面の**何もないところ**を長押しする（アイコンが揺れ出す）
2. **左上の「編集」** → **「ウィジェットを追加」**
3. 上の**検索欄にアプリ名**を入れる
4. 見本を左右にスワイプしてサイズを選び、**「ウィジェットを追加」**
5. 右上の**「完了」**

同じ「編集」の中の「カスタマイズ」は外観（ライト／ダーク／着色／クリア）を
変えるところで、3-4 のマトリクスで使う。

**1 ページにまとめて置く。** 見比べるため。

| 検索欄に入れる | 出てくる名前 | サイズ |
|---|---|---|
| `スパイク` | **スパイク A 静止** | 中のみ |
| 〃 | **スパイク B エントリ切替** | 中のみ |
| 〃 | **スパイク C 1 秒の点滅** | 中のみ |
| 〃 | **スパイク D 4fps** | 中のみ |
| `秒時計` | 秒時計 for Widget | 中 |

**「CharaTime（骨組み）」は置かない。** 本番ウィジェットの土台確認用で、
スパイクとは別のターゲットの別物。

**秒時計を並べるのは切り分けのため**（3-1 の続き）。他社の実装がホーム画面で
秒を刻めているかどうかが、C が止まったときの読みを決める。
秒時計が動いて C が止まれば、原因は手法（マスク書体）の側にある。
両方止まれば、**ホーム画面では拡張の外から描き直されない**ということになる。

**Pixel Pals は無理に置かなくてよい。** 売りは Dynamic Island（面 3）で、
ホーム画面ウィジェットが秒単位で動く保証はない。面 1 の証拠にはならない。

## 4. 判定（0-11）

### 判定の前に片づいたこと（2026-09-22 時点）

C が成立するには部品が 2 つ要る。**その 2 つは、別々にではあるが実機で確認できた。**
残るのは、それが**同時に、しかも拡張が止まった状態で**成立するかどうかの一点。

| 要る条件 | 状態 | どこで見たか |
|---|---|---|
| マスク書体が実機で登録され、右端 1 文字の切り出しが効く | **確認済み** | 下見画面（`--screen spike`）で C の ● 2 つが交互に点灯（§5 ③） |
| タイマー文字が実機のウィジェット面で毎秒描き直される | **確認済み。ただしロック画面で** | 秒時計のロック画面ウィジェット（3-1）。ホーム画面は未測定 |
| 上の 2 つが、**拡張が止まったホーム画面のウィジェットで同時に**成立する | **未確認**。ここがスパイクの本題 | 3-3 以降 |

見込みは上がったが、**Conditional Go の想定は下げない**。報告されている破損条件
（Xcode 26.1 以降の SDK × iOS 26.1 以降）は、部品ごとの動作を止めるのではなく
「拡張が止まっているあいだの描き直し」を止めるものだからである（`research/F` §2）。
上の 2 つがどちらも生きていることは、**破損が報告されている箇所には触れていない**。

| 判定 | 条件 | 面 1 の位置づけ |
|---|---|---|
| **Go** | **C が kill 後も解除後も安定して動く** | 「動く窓」。`ambient1fps` を既定に。D は任意 |
| **Conditional Go** | **C は不安定だが B は安定** | 「様子が変わる窓」。`timelineTransition` を既定に。**プランの他の部分は変わらない** |
| **No-Go** | **B も不安定** | ウィジェットの約束を「1 時間ごと」に下げ、待受モードと壁紙セットの比重を上げる |

**現時点の見込みは Conditional Go**（`research/F` §2 の報告のため）。

Conditional Go でも困らない作りになっている。`RenderCapability` の梯子が
静止画まで自動で落ちるので、**「キャラが消えた」だけは起こらない**。

## 5. 中身のしくみ

### マスクフォント

`tools/spike/make_mask_fonts.py` が fontTools で 2 本の TTF を作る。

- `CTSpikeMaskEven` — 偶数の数字（0,2,4,6,8）が 1em の塗りつぶし、奇数は空
- `CTSpikeMaskOdd` — その裏返し

すべてのグリフを 1em 幅にそろえ、**文字列の右端 1em だけを切り出す**。
右端は必ず秒の一の位で、その偶奇は秒の偶奇と同じ。

### 作りながら分かったこと（①② は 2026-09-12 シミュレータ、③ は 2026-09-22 実機）

**① `Text(timerInterval:)` には合字（GSUB の `liga`）が適用されない。**

`research/E` §2.3 は「`:` + 2 桁を合字で 1 グリフにする」案を書いているが、
手元（Xcode 26.6 / iOS 26.5 シミュレータ）では効かなかった。

| 試したこと | 結果 |
|---|---|
| `Text("05:24")` にマスク書体 | 四角が出る。**合字は効く** |
| `Text("05:23")` にマスク書体 | 何も出ない。正しい |
| `Text(timerInterval:)` にマスク書体 | **何も出ない。合字が効いていない** |

タイマーの文字だけが別の経路で組まれているらしい。
そこで **合字をやめ、右端 1 文字を切り出す方式**に変えた。こちらなら合字が要らない。

**② フォントの PostScript 名（name ID 6）が無いと iOS は登録しない。**

`FontBuilder.setupNameTable` に `familyName` と `styleName` だけ渡すと
PostScript 名が入らず、`UIAppFonts` に書いても登録されない。
`Font.custom` は**黙ってシステムフォントに落ちる**ので、
マスクが数字の形になり、点滅しているように見えない。

**③ マスク書体は実機でも効いた（2026-09-22 確認）。**

`scripts/ios-device.sh --install --screen spike` で実機（iPhone 17 Pro / iOS 26.1）に
入れて下見画面を見たところ、**C の ● 2 つが交互に点いた**。
書体が `UIAppFonts` から登録され、右端 1 文字を切り出す方式が
シミュレータだけの現象ではないことが分かった。

**ただしこれで分かるのは「マスク書体が正しく効くか」だけ。**
アプリは自分で動いているので、`Text(timerInterval:)` が更新されるのは当たり前。
**スパイクの本題は「ウィジェット拡張が止まっていても OS が描き直すか」**で、
それはホーム画面にウィジェットを置いて実機で見るしかない。

それでも、これで**判定の前提**は片づいた。以降 C が動かなければ、
原因は書体ではなく「拡張が止まっているあいだ OS が描き直さない」ことに絞られる。

### 1 秒より細かくする方法（D）

起点を 0.25 秒ずつずらした 4 本を重ねる。`e` を起点からの経過秒とすると、
`j` 本目が点くのは `floor(e + j/4)` が偶数のとき。
点いている ● の数は `4 → 3 → 2 → 1 → 0 → 1 → …` と **0.25 秒ごとに変わる**。

1 秒に 4 回変われば 4fps。**● の数を数えるだけで速さが読める**ので、
写真に撮らなくても目で判断できる。
